# Recover persistently only from transient failures

After a `VoiceConnection` first becomes operational, transient network loss and Voice Gateway close code `4015` start **Transport Recovery** by attempting a version 8 resume. A rejected or invalid resume starts fresh voice coordination for the authoritative channel. Recoverable attempts have no fixed count limit and use exponential backoff with jitter and a capped delay while the main-Gateway voice state still places the bot in that channel; the initial `connect()` operation remains deadline-bound.

A `VOICE_SERVER_UPDATE` with a null endpoint closes the old transport and waits for fresh main-Gateway coordination instead of reconnecting to that server. When a null endpoint explicitly marks an allocated server as unavailable, its later replacement may use the still-authoritative current `session_id`; this failover path is distinct from channel movement, which requires the new session. Close codes `4014`, `4021`, and `4022`, Discord protocol or configuration errors, and unknown application close codes are terminal and never retry automatically. Explicit disconnect, an authoritative external disconnect, or plugin teardown always stops recovery.
